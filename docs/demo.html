为什么 code review 抓不住它

三类真实翻车，每类都见过不止一次。文件看着完美，坏的都在“运行那一刻”。

😵 函数被静默吞掉
AI 改代码用正则替换，一不小心把下一个函数整个删了。HTML 打开一切正常，用户点按钮——没反应。
🙈 说的和做的不一样
页面自称“全部 5 种状态”，里面手工铺的演示数据只有 4 种。人眼全漏过，用户一眼撞上。
👻 样式凭空消失
CSS 类名改了，JS 里的模板没跟上。内容都在、文字都对，屏幕上是一坨没排版的裸文字。

它不是拍脑袋写的

从生产环境用了几个月的质检方法里提炼，背后是 33 条踩坑记录——每一条都真实翻车过至少两次。

01
jsdom 40 项全绿，真机整屏空白
一张翻转卡片被入场动画盖住了正面，机器检查“内容都在”全部通过。所以文档里写清了：动画类缺陷必须真浏览器补一刀——工具知道自己的边界。
02
弹层“点了没反应”的全绿假象
弹层挂在隐藏页面里被折叠成 0×0，检查只看“显没显示”就放行。现在的门禁会量真实几何，不在视口内就是不合格。
03
一条断言盖住 28 个假通过
上一轮的提示残留没清空，后面 28 项“是否弹出提示”全被蒙混过关。现在每轮点击前强制清场。这类坑文档里还有 30 条。
